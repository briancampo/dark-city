## 2. Dispatched Scope & Acceptance Criteria

### Ticket [1.1.0] Containerized Backend Deployment (Docker)

- **Role:** System Architect
- **Directory Ownership:** `docker/`, `Dockerfile`, `docker-compose.yml` (and backend configuration in `crates/dark_city_server/`)
- **Blueprint Reference:** [§2 (System Architecture)](../../docs/dark-city-blueprint.md#2-system-architecture-overview), [§12 (Networking & API Surface)](../../docs/dark-city-blueprint.md#12-networking--api-surface)
- **Goal:** Provide a container definition (Dockerfile / compose) for the Dark City backend runtime that connects to external PostgreSQL (+ pgvector) and external inference servers via environment variables.
- **Acceptance Criteria:**
  - Multi-stage `Dockerfile` creating a lightweight, minimal production image for `dark_city_server`.
  - `docker-compose.yml` demonstrating deployment with external service configuration placeholders (`DATABASE_URL`, `INFERENCE_GATEWAY_URL`, `SERVER_HOST`, `SERVER_PORT`).
  - Container health check integration configured against `/health` (or `/api/v1/health`).
  - Container boots, runs pending migrations on startup, and cleanly shuts down on SIGTERM/SIGINT.
