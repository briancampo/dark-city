## 2. Dispatched Scope & Acceptance Criteria

### Ticket [1.1.1] Postgres + pgvector Provisioning & Base Migrations

- **Role:** System Architect
- **Directory Ownership:** `migrations/`, `crates/dark_city_server/`
- **Blueprint Reference:** [§2 (System Architecture)](../../docs/dark-city-blueprint.md#2-system-architecture-overview), [§4.1 (Memory Schema — now also covers `world_events`/`observable_events`)](../../docs/dark-city-blueprint.md#41-schema), [§10.2 (World Instances & Multi-Tenancy)](../../docs/dark-city-blueprint.md#102-world-instances--multi-tenancy)
- **Goal:** Set up `sqlx` migrations under `migrations/` that enable the `vector` extension and establish: the `worlds` table; the base `citizens` and `simulation_events` tables, both scoped to it; the new `world_events` table for events no citizen caused; and the `observable_events` view that unions `simulation_events` and `world_events` into a single read surface — so every later schema is multi-tenant-ready from day one (Decision 0003), and the Observation module and the Narrator have one thing to query from day one too (Decision 0004).

- **Acceptance Criteria:**
  - `0001_initial_schema.sql` enables `CREATE EXTENSION IF NOT EXISTS vector;`.

  - **`worlds` table created** (`id UUID PRIMARY KEY`, `scenario_id TEXT`, `name TEXT`, `status VARCHAR(16) DEFAULT 'initializing'`, `sim_clock TIMESTAMPTZ`, `created_at TIMESTAMPTZ`) per Blueprint §10.2.

  - Base **`citizens` table** created (`id UUID PRIMARY KEY`, `world_id UUID NOT NULL REFERENCES worlds(id)`, `name TEXT`, `created_at TIMESTAMPTZ`).

  - Base **`simulation_events` table** created with `world_id UUID NOT NULL REFERENCES worlds(id)`, JSONB payload support, and an index on `world_id`, `citizen_id` / `occurred_at`. **Per [Decision 0004](../../decisions/0004-observation-and-world-event-capture.md), this table also gains:**
    - **`location_node_id TEXT`** (nullable) — the real column the Observation module's proximity join filters on. Do not leave this buried in the JSONB payload only.
    - **`salience SMALLINT NOT NULL CHECK (salience BETWEEN 1 AND 10)`** — populated by whichever module logs the row (Skill Execution, Talking, etc.), typically drawn from the acting tool's `default_salience` (Blueprint §5.2). This is _predefined by the producer at write time_ — nothing downstream infers it later.
    - `simulation_events.occurred_at` represents **simulated world-clock time**, not wall-clock insertion time. Do not populate it via `DEFAULT now()`.

  - **`world_events` table created (new — Decision 0004, Blueprint §4.1):**

    ```sql
    CREATE TABLE world_events (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        world_id UUID NOT NULL REFERENCES worlds(id),
        source VARCHAR(20) NOT NULL
            CHECK (source IN ('scenario_scripted', 'threshold_crossing', 'citizen_triggered')),
        origin_citizen_id UUID REFERENCES citizens(id),
        event_type VARCHAR(64) NOT NULL,
        location_node_id TEXT,
        payload JSONB NOT NULL,
        salience SMALLINT NOT NULL CHECK (salience BETWEEN 1 AND 10),
        occurred_at TIMESTAMPTZ NOT NULL,
        created_at TIMESTAMPTZ NOT NULL DEFAULT now()
    );
    CREATE INDEX ON world_events (world_id, occurred_at);
    CREATE INDEX ON world_events (world_id, location_node_id) WHERE location_node_id IS NOT NULL;
    ```

    Notes for implementation — these are acceptance criteria, not suggestions:
    - **`origin_citizen_id` is nullable and provenance-only.** It's populated only for `citizen_triggered` rows and exists for attribution (e.g., the Narrator saying who started a fire), never as an M2 signal — the causing tool call is already separately logged, and separately M2-eligible, in `simulation_events`.
    - **`occurred_at` must be populated explicitly as simulated time** (the world's `sim_clock` value at the moment the row is produced). **It must never use `DEFAULT now()`.** A headless tick doesn't run 1:1 with wall time, so defaulting this column would silently misdate every row.
    - **`created_at`** is the only column on this table that should default to real wall-clock time, and it exists for ops/debugging only — never use it in place of `occurred_at` for anything simulation-facing.

  - **`observable_events` view created**, unioning `simulation_events` and `world_events` for any consumer (the Observation module, the Narrator) that needs "everything nearby regardless of who or what caused it":

    ```sql
    CREATE VIEW observable_events AS
    SELECT world_id, id AS event_id, citizen_id AS actor_citizen_id, location_node_id, occurred_at, salience, payload
    FROM simulation_events
    UNION ALL
    SELECT world_id, id AS event_id, origin_citizen_id AS actor_citizen_id, location_node_id, occurred_at, salience, payload
    FROM world_events;
    ```

  - Migration runner helper implemented in `dark_city_server::db` with connection pool initialization (`PgPoolOptions`).

### Schema Pitfalls to Avoid (Decision 0004)

These are easy to get wrong by habit (e.g., copy-pasting a `TIMESTAMPTZ NOT NULL DEFAULT now()` pattern from elsewhere in the schema) — check for them explicitly before opening the PR:

- **Never `DEFAULT now()` on a simulated-time column.** `world_events.occurred_at` and `simulation_events.occurred_at` both represent the world's own `sim_clock`, not wall time. `world_events.created_at` is the _only_ column meant to default to real insertion time, and it's for ops/debugging only.
- **Don't skip the `observable_events` view.** It's a small addition, but the Observation module (Backlog 1.2.8) and the Narrator's revised query (Backlog 2.3.2) both depend on it as their one read path — without it, those tickets have nothing to build against.
- **Don't let `world_events.origin_citizen_id` become an M2 signal anywhere downstream.** It's provenance only. If you find yourself writing a query that treats it like a culpability marker, stop — that's a sign the query belongs against `simulation_events` instead.
