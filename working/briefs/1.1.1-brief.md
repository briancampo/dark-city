## 2. Dispatched Scope & Acceptance Criteria

### Ticket [1.1.1] Postgres + pgvector Provisioning & Base Migrations

- **Role:** System Architect
- **Directory Ownership:** `migrations/`, `crates/dark_city_server/`
- **Blueprint Reference:** [§2 (System Architecture)](../../docs/dark-city-blueprint.md#2-system-architecture-overview), [§4.1 (Memory Schema)](../../docs/dark-city-blueprint.md#41-schema), [§10.2 (World Instances & Multi-Tenancy)](../../docs/dark-city-blueprint.md#102-world-instances--multi-tenancy)
- **Goal:** Set up `sqlx` migrations under `migrations/` that enable the `vector` extension and establish the `worlds` table plus the base `agents` and `simulation_events` tables, both scoped to it.
- **Acceptance Criteria:**
  - `0001_initial_schema.sql` enables `CREATE EXTENSION IF NOT EXISTS vector;`.
  - **`worlds` table created** (`id UUID PRIMARY KEY`, `scenario_id TEXT`, `name TEXT`, `status VARCHAR(16) DEFAULT 'initializing'`, `sim_clock TIMESTAMPTZ`, `created_at TIMESTAMPTZ`) per Blueprint §10.2.
  - Base `agents` table created (`id UUID PRIMARY KEY`, **`world_id UUID NOT NULL REFERENCES worlds(id)`**, `name TEXT`, `created_at TIMESTAMPTZ`).
  - Base `simulation_events` table created with **`world_id UUID NOT NULL REFERENCES worlds(id)`**, JSONB payload support, and an index on `world_id`, `agent_id` / `occurred_at`.
  - Migration runner helper implemented in `dark_city_server::db` with connection pool initialization (`PgPoolOptions`).
